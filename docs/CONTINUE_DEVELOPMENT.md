# 在另一台电脑继续开发

这份交接面向下一位开发者或 Agent。它只依赖公开源码、文档与自有样本，不需要原工作电脑上的 Axure、逆向工具、会话记录或账号文件。

## 项目目标与当前边界

目标保持三项：尽可能覆盖 Axure 核心功能；以正式公开项目交付原创代码和完整说明；让维护者能把源码带到自己的 Mac，继续开发苹果版本。公开源码或发布一个预览版不能视为全部功能目标完成。

当前源码版本是 **0.2.0-preview.11**，Agent schemaRevision **13**。本轮增加项目全局参考线，以及基础元件/母版/本地库统一拖入吸附；普通页面及自适应视图共用项目线，母版仅用本地线。preview.10 的真实页面目录、混合树和递归删除继续保留，目录不进入画布/标签/预览页面。含目录或非空项目线的 RP 导出仍拒绝。

本轮 Windows 的 12 组相关回归在固定的 64 个应用/清单文件下通过，模型/接口 424 项、成品桌面 19 项、成品 MCP 20 项通过，897 个成品文件与源码一致；没有重跑全部 test-all 入口。范围和失败记录见 [发布记录](RELEASE_NOTES.md) 与 [本版验证摘要](verification-preview.11.json)。preview.10 的 [历史验证摘要](verification-preview.10.json) 和 preview.9 的 [历史验证摘要](verification-preview.9.json) 保留原样，不计入 preview.11 的通过数量。Mac 开发路径已准备，尚未在 Mac 真机执行。

维护会话已实际读取 preview.11 窗口的 state 与 schemaRevision 13，没有为连接核查修改用户工程；先前旧桥接 `APP_NOT_RUNNING` 已被后续成功读取取代。隔离测试写入与当前客户端连接是不同证据。迁移电脑后重新连接并核对实际版本，不复用旧连接令牌。

预览版的版本号以 `package.json` 为准；工程格式和 Agent schemaRevision 分别管理。先核对运行窗口版本，避免把 Agent 连接到另一版应用。

## 在 Mac 上开始

**窗口：Finder。**解压迁移源码包，或克隆公开仓库到自己可写的开发目录。不要把 Windows `node_modules`、EXE、连接文件、恢复目录或账号配置当成 Mac 环境搬过去。需要继续编辑的个人工程另行复制，不能放进公开仓库。

**窗口：终端。**进入仓库根目录，检查当前代码版本和 Node.js 版本，然后按 Mac 指南安装依赖、运行模型测试并启动原搭。安装脚本和打包路径若出现平台错误，先修复可复现的定位问题，保留错误输出，不假定文件扩展名替换即可完成移植。

**窗口：原搭。**用公开样本检查新建/打开/保存、画布编辑、撤销、输入草稿、图片和预览。再让本机 MCP 客户端读取并修改一份自有样本，验证版本冲突、撤销和真实保存。测试与个人工程用独立运行目录。

页面目录可用 `samples/yuanda/页面目录体验.yuanda` 继续：四张真实页和三个目录提供嵌套与跨页跳转。核对页面面板底部父项下拉、混合同级排序、Cmd+方向键、目录删除/撤销与 Agent 并发；不要只检查树行显示。

项目参考线可用任意两页示例继续：确认跨页及实际自适应视图坐标一致，母版不继承项目线，库拖入预览与落点一致；再检查全局修改冲突、保存重开、HTML 无辅助线与 RP 明确拒绝。这些是下一台电脑开发时的范围，不是要求原用户再次手工验收。

最后再构建 Mac 应用并从成品启动。未在 Mac 真机执行的项目继续记为未验证。签名、公证、权限提示、Apple Silicon 与 Intel 架构差异需要独立处理，不从 Windows 检查结果推断。

## 下一批开发优先级

| 方向 | 保留范围 |
| --- | --- |
| 高频桌面编辑 | 页面目录、项目参考线和拖入吸附已接入；继续大目录与跨功能验证，补自动画布、页面背景/设备预设、布局与间距、深层定位、多显示器和参考线打印/视图继承 |
| 交互与数据 | 事件/动作编辑、变量与函数、面板与数据列表组合、专用元件 |
| 绘制和文档 | 流程图、布尔几何、可编辑 SVG、连接线、资源去重、多字段注释与规格输出 |
| 文件互通 | 页面目录及项目参考线的 RP 兼容仍缺；继续有限 RP 扩展、原生验证样本、导入/往返、RPLIB、故障恢复与合并 |
| 平台和协作 | Mac 真机与发行、Agent 完整操作链、独立团队云服务与外部工具集成 |

具体未完成点必须回到能力编号逐项确认。新实现覆盖某个子集时更新其状态，不能删除同一条里难做的余项。功能设计优先考虑鼠标、模型、保存、撤销、Agent 和 HTML 的一致行为。

**H04 项目全局参考线**已在 preview.11 接入。剩余参考线范围是 **H05 显示层次/打印/边距**与 **H07 视图专属线及继承规则**；当前全局线在全部真实页面视图使用相同坐标，不按尺寸缩放。下一项可优先选择页面/画布基础体验（P08–P12），先按能力编号确定一个可独立验证的范围，不把此建议写成已完成。

参考线入口为 `app/core/guide-model.mjs`、`design-model.mjs`、`app/renderer/workspace-tools.js`、`editor-shell.js`；库拖入共用 `drag-preview.js`。`setProjectGuides` 是顶层命令，完整替换两个方向的坐标数组，不能包装成当前视图或母版命令。专项入口为 `node --test tests/global-guides.test.mjs`、`node scripts/test-global-guides-ui.mjs` 和 `node scripts/test-drag-preview.mjs`；生产主进程/stdIO MCP 另由 `scripts/test-agent-mcp-desktop.mjs` 检查。

本轮目录代码入口为 `app/core/page-tree-model.mjs`、`app/renderer/navigation-model.mjs`、`navigation-tools.js` 和 `workspace-tools.js`。旧 `reorderPage` 仍是兼容入口，新混合树必须使用 `reorderPageTreeItem`。新增目录行为时同时检查 HTML 排序、主进程选区保护、Agent 契约、库条目边界和 RP 拒绝提示。专项入口为 `node scripts/test-page-folders-ui.mjs` 与 `node --test tests/page-folders.test.mjs`；完整检查入口仍是 `npm run test:all`。

## 发布与验证交接

本轮发布完成后，应能从仓库 README/Release 取得实际版本、提交、发行文件和验证说明。接手时检查远端与本地的真实状态，不以本文或旧聊天中的“已上传”作为证明。若没有对应发行检查记录，应重新检查或明确标为未知。

运行模型、相关 UI/HTML、桌面/MCP 与成品核对；输出记录包含平台、版本、命令、替身、未覆盖范围。保留失败和修复后的结果。`.local/` 中的个人环境证据不默认公开；需要分发的结果应另做去除路径和敏感内容的摘要。

源码公开清单必须排除商业程序及反编译材料、研究工具、缓存、个人项目和临时令牌。`.yuanda` 仍是完整工程；RP 只覆盖已声明子集，没有通用导入器，不能仅保留 RP 后删除工程。
