# 原搭 0.2 开发接口约定

本文对应 0.2.0-preview.10 源码、Agent schemaRevision 12。页面目录的验证结果以本轮发行记录为准。应用版本、Agent 契约修订号和项目文件版本分别管理。实际可查询契约见 `app/agent-schema.mjs`；运行中的应用以 `GET /v1/schema` 为准。

所有应用实现与 HTML 运行器均为原创代码。这里描述原搭自己的行为，不构成 Axure 文件或全功能兼容承诺。

## 1. 项目格式与规范化

`.yuanda` 为 UTF-8 JSON，文件版本仍为 1：

```text
Project {
  format: "yuanda", version: 1, id, name,
  pages: Page[], pageFolders: PageFolder[], pageTreeOrder: null | string[],
  styles: SharedStyle[], components: Component[], variables: Variable[], viewSets: ViewSet[]
}
Page {
  id, name, width, height, background, nodes: Node[],
  parentId: null | pageId | folderId,
  guides: {horizontal: number[], vertical: number[]},
  groups: Group[], annotation: string,
  views: AdaptiveView[], interactions: Interaction[], viewSetId: null | viewSetId, viewOverrides: {}
}
PageFolder { id, name, parentId: null | pageId | folderId, collapsed: boolean }
Node {
  id, type, name, x, y, width, height, rotation, visible, placed, locked, text, src,
  style: Style, // 基础与扩展字段见第 11 节
  interactions: Interaction[],
  annotation, styleId, checked, options, value, radioGroup, rows,
  inputType, readOnly, maxLength,
  disabled, selected, error, stateStyles, bindings, panel, repeater,
  path, connector, richText, image
}
```

字段由元件类型决定用途；不能向任意类型塞入不适用的数据。16 种类型：

```text
rectangle text button input image ellipse line textarea
checkbox radio select table dynamicPanel repeater path connector
```

`DocumentEngine` 构造和替换文档时先对副本规范化，再完整校验。旧 v1 项目缺少新增字段时补默认值，不修改调用者传入对象；显式提供的非法值不会被静默“修正”。ID 在项目内唯一，节点/状态/行/组等引用必须有效，页面层级和容器不得循环。

图片只接受内嵌 PNG/JPEG/WebP/GIF，单张最多 4 MiB；不依赖外链图片。图片编辑字段及完整限制见第10节。非法属性、任意 JavaScript 和脚本 URL 不属于契约。

### 页面和文件夹（schemaRevision 12）

`pages` 只含可绘制、可跳转的真实页面。`pageFolders` 是独立的组织结构，没有 `nodes`、尺寸、样式或页面交互；页面与文件夹的 `parentId` 都可指向另一页面或文件夹，或以 `null` 表示顶层。ID 在整个工程中唯一，禁止自身/后代循环和不存在的父项。

旧工程缺少目录字段时补 `pageFolders:[]`、`pageTreeOrder:null`。`null` 沿用 pages 数组顺序，再列目录；显式 `pageTreeOrder` 必须恰好包含每个页面和文件夹 ID 一次。它是全量混合顺序，父级关系决定层级；界面和 HTML 通过深度优先遍历得到展示顺序，不能直接把数组第一项当成真实首页。

文件夹 `collapsed` 缺省为 `false`，会保存并参与撤销；它只影响编辑器树的可见性，不从工程或 HTML 删除后代。普通页面的树折叠保存在本机工作区偏好，未写入 Page。树选中文件夹与当前编辑画布分开，Agent 的 `yuanda_select.pageId` 与交互 `navigate.pageId` 仍必须是真实页面，不能传文件夹 ID。

### 表单字段

| 字段 | 取值和语义 |
| --- | --- |
| `inputType` | 默认 text；仅 input 可选择 text、password、number、email、date、tel、url、search。 |
| `readOnly` | 默认 false；input/textarea 可为 true，阻止访客键盘输入，但仍可聚焦、选中文本及由交互设置值。 |
| `maxLength` | 默认 null，不限；input/textarea 可设 0–50000 的整数。number/date 必须为 null。按原生 UTF-16 用户输入长度限制，不裁剪保存值或交互设值。 |
| `disabled` | 控件禁用状态，与只读不同；导出控件不可正常聚焦或操作。 |
| `checked/options/value/radioGroup/rows` | 对应勾选、下拉、输入、单选组和普通表格数据；具体结构由 schema/模型校验。 |

`maxLength:0` 表示不允许继续输入字符；它不是清空现有值的动作。设置初值或交互值不会模拟浏览器表单提交校验，类型效果应在真实预览中检查。

## 2. 复用模型

```text
SharedStyle {id, name, style}
Component {id, name, width, height, background, annotation, guides, groups, nodes, views, viewOverrides}
Group {
  id, name, nodeIds, locked, placed, parentGroupId: null | groupId,
  componentId: null | componentId,
  x, y, sourceIds, internalIds,
  overrides: {[sourceId]: {text?, src?}},
  viewMode: "fixed" | "auto", viewId: null | componentViewId,
  viewOverrides: {[hostViewId]: {x?, y?, placed?}}
}
```

共享样式通过节点的 `styleId` 关联。修改定义会同步关联节点；直接调整节点外观只增加 styleOverrideKeys 局部覆盖，保留样式关联；清除覆盖可恢复继承。删除定义保留已有外观。

母版定义是一张真实可编辑画布，至少含一个节点。新增定义默认白色背景、空注释、空参考线及空组。组件实例以关联 Group 表示，`sourceIds` 与 `nodeIds` 一一对应；状态/行等内部 ID 由 `internalIds` 映射，不能手工复用。

母版可嵌套另一个母版，按依赖顺序同步；循环、超过 16 层以及超出模型节点限制的结构会被拒绝。删除定义或解除实例关联保留各已有宿主视图外观，变成普通内容。母版有自身持久化 `views/viewOverrides`，没有页面级 `parentId/interactions`；内部节点仍支持交互。组件视图与页面自适应视图的区别及匹配规则见第 8 节。

实例覆盖只允许 `text` 和图片 `src`。它们不抹掉母版后续的位置、尺寸、样式和交互更新；清除后恢复跟随主定义。锁定的实例或源元件不能越权覆盖。

普通组可用 `parentGroupId` 嵌套，深度最多 32；父组包含子组成员，不能循环、重复归属或跨真实容器混合建立嵌套结构。历史项目中的跨面板状态顶层组会保留为兼容条目。概览树从组、面板状态和中继器模板推导，不另存一份可能失步的树。祖先组或容器锁定时，内部节点不能通过旧指令绕过保护。

组缩放调整位置和几何尺寸，不缩放字体；含关联母版实例的组须先解除关联，或去母版定义中修改。旧跨状态组可显示和保存，整体改变归属前须先解组。含当前行绑定的内容移出列表会拒绝，以免默默丢失绑定。概览折叠只在当前窗口保留，未实现跨启动记忆、拖动边缘自动滚动或超大项目性能保证。

## 3. 交互与表达式

```text
Interaction {
  event, name, enabled,
  caseMode: "if" | "elseIf" | "else",
  condition: null | Expr,
  actions: Action[]
}
Variable {name, type: "string" | "number" | "boolean", value}
```

页面与节点均可存 interactions。可配置的事件以运行中 schema 的 `eventsByTarget` 为准：普通鼠标、键盘与加载事件，输入控件的输入/值变化，动态面板的状态/拖动/滚动，以及页面专属的自适应变化、窗口尺寸/滚动和变量变化。UI 与 Agent 使用同一能力表。

每个 if 开启一个分支组，后续 elseIf/else 属于该组；组内选择第一个满足条件的分支，独立 if 组各自判断。缺省按条件自动运行，动作在分支内依次执行。

页面/节点的 `eventSettings` 形如 `{click:{enabled:true,executionMode:"automatic"}}`，未配置等同于启用且自动运行。`executionMode:"menu"` 则在条件选出的有效分支中让访客选择一项，Esc 或点击外部取消；没有启用动作的分支不出现在菜单中。旧文件不会自动改为菜单行为。

事件设置、分支 `enabled` 和动作可选的 `enabled` 是独立开关，动作省略时默认启用。停用事件不改变分支和动作各自的设置。`updateNode/updatePage.patch.eventSettings` 整体替换该字典，修改某个事件时保留其他事件条目。保存、撤销和复制均保留这些字段。

`focus {targetId}` 聚焦输入框、多行文本框、选择框、按钮或勾选控件；`triggerEvent {targetId,event}` 运行同画布目标的有效事件，保留重复器当前行作用域。相互触发超过 32 层会停止并提示，表达式仍不执行字符串代码。`setAdaptiveView {mode:"auto"|"base"|"view",viewId?}` 可以在交互编辑器配置，指定视图必须来自当前页面。

`Expr` 是安全的可序列化树，不是待执行代码：

```text
字面量：string | finite number | boolean | null
变量：  {op:"var",name}
节点：  {op:"node",nodeId,property}
事件：  {op:"event",name}
当前行：{op:"item",column}
行信息：{op:"row",property:"id"|"marked"}
列表统计：{op:"repeater",repeaterId,property:"currentPage"|"pageCount"|"pageSize"|"totalCount"|"filteredCount"|"markedCount"}
运算：  {op,args:Expr[]}
```

运算符：`eq/neq/gt/gte/lt/lte/and/or/not/add/sub/mul/div/concat/contains/length`。节点可读取 `text/value/checked/visible/disabled/selected/error/x/y/width/height`，事件可读取 `value/checked/key/x/y/rowId`。行字段只在有效的行上下文中使用。

| 动作 | 参数 |
| --- | --- |
| `setText/setVisible/setValue/setChecked/setSelected/setDisabled/setError` | `{targetId,value:Expr}` |
| `toggleVisible` | `{targetId}` |
| `navigate`、`wait` | `{pageId}`、`{ms}`，等待范围 0–60000 毫秒 |
| `setVariable` | `{name,value:Expr}` |
| `move`、`resize` | `{targetId,x:Expr,y:Expr,relative}`、`{targetId,width:Expr,height:Expr}` |
| `setStyle` | `{targetId,style:partialStyle}` |
| `setPanelState` | `{panelId,stateId}` |
| `nextPanelState/previousPanelState` | `{panelId,wrap}` |
| `addRows` | `{repeaterId,rows:[{values:{columnKey:Expr}}]}` |
| `deleteRows/filterRows` | `{repeaterId,where:null或Expr}` |
| `updateRows` | `{repeaterId,where:Expr,values:{columnKey:Expr}}` |
| `sortRows` | `{repeaterId,column,descending}` |
| `setRepeaterPage/setRepeaterPageSize` | `{repeaterId,value:Expr}`；每页数量 null 表示显示全部 |
| `markRows` | `{repeaterId,where:null或Expr,marked:Expr}`；仅当前行可比较 row.id 与 event.rowId |

表中的每个动作对象还需 `type`。节点动作目标必须在本画布内有效，页面跳转指向真实页面；变量、面板状态和数据列也必须存在。

### 容器与自适应视图

```text
Panel {
  states:[{id,name,nodeIds}], initialStateId, clip
}
Repeater {
  columns:[{key,label,type}], rows:[{id,values}], templateIds,
  itemWidth,itemHeight,layout:"vertical"|"horizontal"|"grid",gap,columnsCount,
  filter:null|Expr, sort:null|{column,descending},
  pagination:{pageSize:null|integer(1..10000),initialPage:integer(1..10000)},
  markedRowIds:rowId[]
}
AdaptiveView {
  id,name,minWidth,width,height,overrides:{[nodeId]:partialNode}
}
```

动态面板和中继器仍引用当前画布的节点，不能跨画布引用。移动容器应使用专用命令。中继器模板按数据行重复显示，可读取当前行字段；原型运行时数据变化不反写设计数据。

列表先筛选、稳定排序，再按页显示；页码自动收敛到有效范围。空结果为第 1/1 页、0 行。翻页和筛选隐藏行，不销毁该行输入、面板和内层列表状态；删除行才销毁。标记按稳定行 ID 记录。浏览器运行时页码、标记与输入不会回写设计文件；设计时的初始配置会保存。分页按钮由普通按钮和动作组合，系统不自动追加工具条。

旧独立自适应视图选择不超过浏览器宽度的最大 minWidth，没有匹配使用基础页面。新的共享视图集支持多层继承，窄于最小断点时选择最小视图。普通属性编辑已接入明确的当前/全部视图事务，不再依赖专用覆盖弹窗；字段范围、兼容行为与原点/放置规则见第 8 节。

### 矢量与富文本

```text
Path {closed,points:[{x,y,inX,inY,outX,outY}]}
Connector {
  from:{nodeId,side},to:{nodeId,side},
  route:"straight"|"elbow",arrow:"none"|"end"|"both"
}
RichText {
  fontFamily,lineHeight,
  paragraphs:[{align,list:"none"|"bullet"|"number",
    runs:[{text,bold,italic,underline,color:null|hex}]}]
}
```

路径锚点使用元件内归一化坐标，控制点成对提供或同时为 null；连接线关联当前画布节点。富文本是结构化段落和文本片段，不接受任意 HTML；节点纯文本需要与富文本内容一致。

## 4. 文档引擎与完整命令表

`app/core/document.mjs` 导出 `createBlankProject/createDemoProject/makeNode/validateProject/DocumentEngine` 等入口。

- `new DocumentEngine(project)`：规范化并验证；`getSnapshot()` 返回深拷贝。
- `revision/canUndo/canRedo`：当前版本和历史状态。
- `apply(commands,{expectedRevision?,label?})`：在副本顺序应用、同步引用并完整验证，成功后一次提交；失败不改变项目或历史。
- 一次事务最多 1000 项实际编辑操作，母版子命令也计入。有效变化一次推进 revision；无变化不推进。当前保留最多 80 次撤销。
- `undo()/redo()`：切换历史并推进 revision。`replace(project)`：验证、替换并重置历史。
- 核心调用的 expectedRevision 可选，但外部 HTTP 修改必须提供。不得绕过主进程，直接改渲染界面里的副本当作保存成功。

以下每个命令对象都有 `type`；问号表示可选。

| --- | --- |
| 元件 | `addNode {pageId,node}`；`updateNode {pageId,nodeId,patch}`；`removeNodes {pageId,nodeIds}`；`reorderNode {pageId,nodeId,index}` |

`updateNode.patch.style` 合并局部字段，interactions 等其他提供字段整体替换。直接更新 text 会移除旧 richText，除非提供新的同步结构。删除节点清理相关引用；不允许删除最后一页。锁定节点/组和关联实例的编辑限制同样适用于 Agent。

数据导入只接受 UTF-8 CSV/Tab 文字，不接受文件路径或 xlsx。最多 4 MiB、100 列、10000 条数据，每个已有目标列必须有明确映射。带引号的分隔符、换行和双引号转义按同一解析器处理；数字必须有效，布尔只接受 true/false、1/0、是/否。追加保留旧行及标记；替换生成新行 ID、清空标记并重置初始页，整批可撤销。

### 页面目录命令的边界

改父级与改顺序是两个命令，可放进同一批提交。`reorderPageTreeItem` 只移动一个 ID 的排序位置，后代通过父级关系随其显示；有效 index 为 `0..总项数-1`。旧 `reorderPage` 仍以真实页面数组计数，保留既有目录槽位；新混合树操作应使用 `reorderPageTreeItem`，不能把同级索引当全量索引。

`removePageFolder` 递归删除目录及全部后代页面/目录，并清理被删页面、元件及内部 ID 的引用；若会删光真实页面则整批拒绝。`removePage` 只删除该页面及其元件，将直接子页面/目录提升到被删页的父级。两者都可在一条历史记录中撤销。目录命令不能混入 `componentCommands` 当作母版内编辑。

人工拖动和菜单/弹窗也有版本保护：项目、revision 或编辑目标变化会取消旧拖动和菜单；命名、递归删除确认提交捕获的版本，冲突后需重读再决定，不能仅替换版本号。Agent 调用仍先读 state/schema、预检并携带 `expectedRevision`。

### 母版画布事务的边界

`componentCommands` 的子命令可省略 pageId，或者使其等于 componentId；targetPageId 也不能指向别处。允许局部元件、复制粘贴、组、共享样式应用、嵌套实例及覆盖、面板和中继器命令。准确白名单为 `document.mjs` 中的 `COMPONENT_EDIT_COMMANDS`。

局部 `updatePage` 只允许 name/width/height/background/annotation/guides。不能再次嵌套 componentCommands，也不能新建/删除全局页面、变量、样式或母版定义；新建母版定义应在普通页面或顶层命令中完成。`updateComponent` 可更新定义本身的字段，但不能直接替换 groups，组结构通过局部命令维护。

### 复制与粘贴

```text
fragment {
  projectId, sourceId,
  nodes: Node[], groups: Group[], views: AdaptiveView[],
  nodeIds: selectedNodeId[],
  viewState?: {kind: "component" | "adaptive", definitions: ViewDefinition[],
    overrides: {[viewId]: {[nodeId]: visualPatch}}, activeViewId: null | viewId},
  appearance?: {base: {[nodeId]: visualPatch}, views: {[viewId]: {[nodeId]: visualPatch}}}
}
```

Ctrl+C 保存整个源画布的 nodes/groups/views 深拷贝及所选 nodeIds；Ctrl+V 对这个快照调用 pasteFragment。当前只接受相同 projectId，不做跨项目资源合并；源页面、元件之后被修改或删除仍可粘贴复制时内容。Ctrl+D 即时捕获当前所选内容，再调用 pasteFragment；Agent 仍可直接使用 duplicateNodes 复制执行时的源内容。

新快照的 `viewState` 保存视图定义和覆盖；`ViewDefinition` 为组件的 `{id,name,parentId}` 或自适应视图的 `{id,name,parentId,minWidth,width,height}`。历史自适应覆盖还可含 text/value/visible/disabled；组件覆盖只接受 visualPatch。`appearance` 保存基础和各视图的已解析外观，供源母版定义删除后恢复复制时外观。视图按完整祖先名称路径匹配；目标共享视图集中缺少对应路径时明确拒绝，不静默改动其他页面共用的视图树。

引擎重新生成并映射节点、状态、数据行和组 ID，保留所复制内部交互关系。pasteFragment 的 idMap 可包含快照中所有节点/内部 ID/组的键，未选中的键忽略；duplicateNodes 的 idMap 范围更严格。不要把两者语义混用。

普通副本解锁；若完整容器被复制，其后代和模板关系一起保留。单独复制子节点时，同画布粘贴且原容器、状态与源节点仍存在，会恢复捕获时的归属；原归属无法恢复或跨画布粘贴时，产生独立内容并清理相应数据绑定。仍存在的母版定义保持关联，后续继续同步；源定义已删除则安全解除关联，保留复制外观。变化或删除的共享样式也会解除关联以保留快照外观。无法保留的外部引用被清理或由校验拒绝，不允许跨容器悬空引用。

## 5. 桌面桥与 Agent

`app/preload.cjs` 只公开固定接口。异步请求失败抛出带 code 的 Error；`onState` 是同步订阅，返回取消函数。

| 接口 | 返回或用途 |
| --- | --- |
| `getState()` | `{project,revision,canUndo,canRedo,filePath,dirty,selection:{pageId,nodeIds},agent,appVersion}` |
| `getSchema()` | 当前可发现契约 |
| `validateCommands({commands,expectedRevision})` | 在副本上预检，返回 `{valid:true,revision,count}`；不变更文档或历史 |
| `command({commands,expectedRevision,label})`、`undo()`、`redo()` | 提交或撤销，返回新 state |
| `newProject/openProject/saveProject/saveProjectAs` | 项目操作，取消可返回 null |
| `exportHtml/preview/exportRp` | `{ok,path?,message?}` 或取消时 null；RP 只接受受支持子集，遇到目录或其他不支持内容时返回原因并停止导出 |
| `importImage()` | `{src,name}` 或取消时 null |
| `getAgentInfo()` | `{enabled,port,connectionFile,cliPath,requests,lastActivity}` |
| `setSelection({pageId,nodeIds})` | 同步普通页面选区，不改项目或发新 state 事件；不能把它当母版编辑目标 |
| `openFolder(kind)` | 固定的 exports/project/docs 目录 |
| `onState(callback)` | 订阅完整状态，返回 unsubscribe 函数 |

主进程持有真实文档和磁盘权限；编辑器提交命令，不自行保存文件。预检后必须仍用检查时版本提交；如果项目变化，要重新检查。

渲染界面保留正在输入的文字草稿。Agent 更新无关内容时不重建输入框；同一文字发生冲突或提交失败时，草稿保留在选择窗口，允许替换当前文字、保留为新节点或采用最新内容。关闭窗口先等待 `flushPendingEdits()` 提交当前输入和命令队列，再进行未保存内容处理；未解决冲突不继续关闭。

HTTP 只监听 127.0.0.1 随机端口，验证 Bearer 令牌和 Host，拒绝网页 Origin。支持 `GET /v1/state`、`GET /v1/schema`、`POST /v1/commands`、`POST /v1/undo`、`POST /v1/redo`。POST JSON 必须含 expectedRevision，commands 请求还含 commands 数组和可选 label。冲突返回 409 / REVISION_CONFLICT，重读后重新计算修改。

**预检支持 MCP、HTTP 与桌面。**`yuanda_validate_commands`、`POST /v1/validate`、桌面桥和工作台都在副本上校验，不修改项目。预检不锁定工程；正式提交仍检查 `expectedRevision`、完整校验并原子应用。旧 CLI `scripts/yuanda-agent.mjs` 支持 state/schema/libraries/library/apply/undo/redo，尚无预检子命令；新增操作使用 MCP 或相应 HTTP 接口。连接方法见 [Agent 接入](Agent接入.md)。

## 6. 保存、HTML 和 RP

保存过程：取主进程文档快照 → 序列化 JSON → 写同目录临时文件并刷入磁盘 → 需要时保留旧文件 .bak → 重命名到目标文件。取消文件窗口不会提交保存；恢复数据单独存储，不替代用户项目。

`exportHtml(project)` 返回单个 HTML 字符串，内嵌模型、图片和原创运行器。用户文本安全转义，表达式不执行 JavaScript，运行中保留动作顺序，切换页面取消旧页未完成动作。变量、输入和数据列表的运行时变化只在当前演示中存在，重新体验重置，不写回 .yuanda。

HTML 以混合树中第一个真实页面作为默认落地页；文件夹不生成可选页面，折叠不隐藏后代页面。改名和移动保留页面 ID，因此现有页面跳转继续指向同一页。

原生 `.rp` 已启用有限导出：矩形、文字、按钮、多页、静态 PNG 和单个无条件单击跳页。基础样本曾经人工打开、编辑、保存、预览和重开；后续图片与跳页的结构检查不等于全部 Axure 版本的原生验收。含页面文件夹（包括空目录）、复杂交互或其他不支持内容时先列原因并拒绝，不静默丢弃；当前没有通用 RP 导入或完整往返。完整编辑数据仍保存为 `.yuanda`，差距见[能力清单](FEATURE_MATRIX.md)。

## 7. 本地元件库和动态面板扩展

`.yuandalib` 是原创 JSON 交换格式：`{format:"yuanda-library",version:1,id,name,description,folders,items}`。文件夹为 `{id,parentId,name,description}`；条目为 `{id,folderId,name,description,warnings,project}`，project 是独立可校验的单画布设计及依赖。不得包含自定义 HTML 缩略图、脚本、文件路径或页面跳转；缩略图由界面安全生成。单库最多 32 MiB、100 条目、200 文件夹、合计 10000 元件（每条目含依赖最多 5000）。

元件库的 `folders` 与项目的 `pageFolders` 是不同结构。库条目的单画布 project 不接受页面文件夹或页面父级；保存选区到库不会把整个项目目录树带入条目。

桌面桥新增 `libraryList()`、`libraryCreate({name,description})`、`libraryLoad()`、`libraryEdit({id,expectedRevision,op})`、`librarySaveSelection({id,expectedRevision,expectedProjectRevision,pageId,nodeIds,name,description,folderId?})`、`libraryRemove({id,expectedRevision})`、`libraryReveal({id})`、`libraryExport({id})`。文件路径只能来自原生文件窗口；取消返回 null。列表返回 `{libraries:[{id,path,sourcePath,library,revision}],errors}`，写操作返回更新后的单库记录；移除返回 `{ok,id}`。revision 是库 JSON 内容的 SHA-256，过期修改返回 `LIBRARY_REVISION_CONFLICT`。保存选区还必须匹配整数项目版本。

`op.type` 支持 updateLibrary、addFolder、updateFolder、removeFolder、addItem、updateItem、removeItem；每个操作只改库，不计入项目撤销。删除文件夹把子文件夹和条目提升到父级。托管副本存于 `data/libraries`（源码运行在 `.local/yuanda-runtime/libraries`），最多 20 库/128 MiB。库移除移入 `.archive`，不删除外部源文件。编辑和导出使用临时文件、备份与原子替换；不自动监听来源文件。

应用内库写入串行执行，并在提交临时文件前再次核对库内容摘要。损坏文件单独报错，不隐藏正常库。不要在原搭写入时用外部编辑器同时修改托管文件：摘要复核不是操作系统级的跨进程比较替换锁；交换和编辑应通过界面或导出的副本进行。

`insertLibraryItem {pageId,item,x?,y?,conflictPolicy:"copy"}` 是项目事务，坐标默认 80,80。节点/组/状态/数据行/依赖资源重新编号，同名资源和变量独立命名。它可用于 `componentCommands`：这是允许导入所需全局依赖的局部插入例外，不允许借此修改既有全局资源。所有依赖和节点与插入同笔撤销。页面剪贴板的同项目限制不变；跨项目复用走库条目。

动态面板新增 `sizeMode:"fixed"|"content"`，`scroll:{x,y}` 每轴为 none/auto/always，`pin:null|{horizontal:"left"|"center"|"right",vertical:"top"|"center"|"bottom",offsetX,offsetY}`，以及 `drag:{enabled,axis:"both"|"x"|"y",bounds:"none"|"parent"|"viewport"}`。旧项目默认固定尺寸、不滚动、不固定、不允许拖动。`setPanelOptions {pageId,panelId,patch}` 按上述一级字段合并；横纵滚动对象要一起提供。`duplicatePanelState {pageId,panelId,stateId,newStateId?,name?}` 复制内部闭包；`reorderPanelState {pageId,panelId,stateId,index}` 不改变显式初始状态。

固定区域为播放器工具条下方的可用视口，内容自适应保留面板原点；预览拖动、滚动、每状态位置不回写设计数据。dragStart/drag/dragEnd/scroll 仅用于动态面板；控件和有点击动作的子对象优先操作。实际边界以测试记录和当前 schema 为准，不推断完整 Axure 滑动手势支持。

## 8. 视图与编辑范围（schemaRevision 7）

`ViewSet={id,name,views:[{id,name,parentId,minWidth,width,height}]}`。Base 用 null 表示，不额外创建 ID。页面以 `viewSetId` 引用共享定义，以 `viewOverrides[viewId][nodeId]` 保存页面专属覆盖。没有共享集时继续读取旧 `page.views`；两套不可同时非空。旧独立视图仍使用单层覆盖；转换到共享集必须完整映射旧视图。共享集宽度不足最小断点时取最小视图，旧独立视图保留 Base 兜底，以免改变旧文件行为。

母版新增 `views:[{id,name,parentId}]` 和 `viewOverrides`；实例组新增 `viewMode:"fixed"|"auto"`、`viewId:null|id`、`placed`、`viewOverrides:{hostViewId:{x?,y?,placed?}}`。实例视图的自动选择按完整祖先名称路径匹配，缺匹配返回 Base。实例组视图覆盖保存的是实例原点与整体置入状态，后续新增源节点仍能跟随。文字/图片实例覆盖继续位于 `group.overrides`。

`viewCommands {pageId,viewId,scope:"current"|"all",commands}` 固定此次编辑目标，不从编辑器当前选中状态推断。母版使用外层 `componentCommands`、内层 `viewCommands`；不能反向或递归嵌套。最多 1000 项实际子操作，仍是一笔原子事务、一次撤销。`moveNodes {pageId,nodeIds,dx,dy}` 扩展容器与完整实例且不重复移动；全部视图平移在各自位置上增加位移，保持不同布局。

`viewCommands` 内的每个子命令必须明确给出与外层相同的 pageId；`componentCommands` 仅自动补它直接一层子命令的 pageId，不递归填充。`setComponentInstanceView` 选择 `viewMode:"auto"` 时，viewId 必须传 null；固定模式才可传组件视图 ID 或 null（Base）。

当前子视图仅对 x/y/width/height/rotation/style/placed 保存稀疏覆盖，逐样式属性继承。全部视图显式设值会清理对应叶覆盖。文字、图片、交互、数据、注释、命名与结构共享；历史 text/value/visible 等覆盖仍可读，明确编辑 text 才清该节点旧 text 覆盖。不能将解析后的整张画布直接写回，因为它包含继承后的值及只读 `effectivePlaced`。

`setNodesPlaced` 按范围置入或取消放置；当前子视图新增只置入该视图及后代，当前子视图删除是取消放置，Base/全部视图删除才移除数据。已有元件转换为面板/列表是共享结构变更，新容器会保留原内容在各视图的放置与包围范围；不把旧内容误当作仅在当前视图新增。`clearInstanceViewOverride` 恢复实例原点/置入继承；`clearViewOverride` 必须指定 paths，页面整份节点覆盖用 `setViewOverride {patch:null}` 清除。母版节点用 `clearComponentViewOverride`，省略 fields 清整份，提供 fields 则只清指定属性。

`setPageViewSet` 需要完整一一 `viewMap`，移转覆盖和视图动作；`detachPageViewSet` 物化成独立视图。为防止自动母版在继承名称变化后回 Base 而丢外观，迁移会保存已有视图的必要视觉值。解除组件关联或删除主定义同样保存宿主已有视图的外观。剪贴板保存复制时的视图数据与外观快照，源定义删除后仍可恢复；依赖还在时保持原关联。库顶层仅 Base 画布，不携带页面视图集/切屏动作；母版依赖可以保留自己的视图并重映射编号。

网页 `setAdaptiveView {mode:"auto"|"base"|"view",viewId?}` 可用于页面及页面元件；`adaptiveViewChange` 仅用于页面，事件包含 viewId、previousViewId、reason（resize/selector/action）。有效视图真的改变才触发，连续相互触发超过 32 层会提示检查条件。切换只更新未被访客或动作改变的布局值，不重建 DOM，不重置输入、变量、状态、数据行或等待。`placed` 与 `visible` 独立，隐藏祖先和取消放置仍约束嵌套/固定面板。

设备尺寸预设、不同尺寸独立的专用控件数据等未列出的行为不能推定已支持。RP 导出状态会把新视图集和取消放置列为未支持内容；不因新增编辑能力解除 RP 验收门槛。

## 10. 图片编辑（schemaRevision 8 起）

`image` 只用于图片节点，其他节点为 null。旧项目缺少此字段时补 `fit:"cover",autoFit:false`，保留旧显示；新图默认 `fit:"stretch",autoFit:true`。完整字段见 `schema.structures.imageSettings`。`src` 保存原图；crop/cuts 为相对原图 0–1 的区域，corners 为原图像素。翻转、滤镜、九宫格、文字和优化副本都不改写原图。

命令包括 `setImageOptions`、`replaceImage`、`cropImage`、`fitImage`、`sliceImage` 和 `clearImage`。它们进入同一事务、修订号检查和撤销记录。图片设置共享所有视图；替换后自动适应和显式 fit 的框尺寸通过 `viewCommands` 遵守当前/全部范围。手动 updateNode 宽高关闭 autoFit。replaceImage 清旧裁剪/角部/挖空/优化；直接 updateNode 改 src 且未提供 image 时也清旧图派生数据。

`setImageOptions.patch` 对 filters/text 做局部合并，其余一级字段完整替换。`cropImage` 保持外框，设为 stretch，关闭角部。`sliceImage.axis` 的 horizontal/vertical/cross 分别为上下、左右、四块；atX/atY 是内部切点。首片保留原 ID，新片重新映射自身交互引用；面板状态、列表模板、普通组与各视图的置入和布局继承原归属。全部视图及状态里的非零边框/圆角、复杂填充、阴影和模糊，以及保留角部、非空图片文字和在各视图显示不同区域的 cover 图，需先关闭相应设置或改为 stretch，命令不会暗中改变显示。片数和图片总量仍受项目上限约束。

优化副本存在 `image.optimization`，设 null 可恢复原图；GIF 优化是静态副本。实际绘制使用解码得到的像素尺寸，不把 Agent 提供的自然尺寸当成像素事实。实例 src 覆盖会清除继承的优化副本与自然尺寸提示，其他共享设置继续跟随母版。图片文字独立于图片层，翻转/滤镜不会影响文字和外框。

桌面 `importImage(context?)` 返回单个 ImageAsset 或 null；`importDroppedImages(files,context)` 接受真实 File，由 preload 提取路径；`readPasteSource({projectId,expectedRevision,internalToken?})` 返回 images/internal/empty。ImageAsset 含 src、name、mime、naturalWidth、naturalHeight、sourceFormat、converted、animated、warnings。读取开始捕获项目、修订号与编辑位置；提交继续使用捕获值，切页不会误导入新目标，修订号变化会拒绝陈旧写入。

`markInternalClipboard({projectId})` 写随机标记，`writeClipboardImage({src})` 复制 PNG。真实图片优先于内部标记；剪贴板变成文字或空时不粘贴旧内部快照。输入控件的文字粘贴不被画布快捷键截获。这些桌面方法只允许可信编辑器主框架，文件/剪贴板操作与关闭协调；HTTP 没有任意路径、剪贴板或系统命令入口。

桌面保留 PNG/JPEG/WebP/GIF 原字节与动画，BMP 和受支持的静态 SVG 转为 PNG 并提示；SVG 不支持脚本、外部资源、foreignObject、动画和滤镜。单张 4 MiB、每批 8 张/24 MiB，每边 8192、总像素 16 Mi，动画最多 300 帧/累计 64 Mi 像素。项目展开后原图/切片/实例/优化副本总量 24 MiB，当前未做资源去重。导出 HTML 内嵌图片，预览变化不回写项目。具体操作系统剪贴板兼容范围以该次实际测试记录为准。

图片头部、PNG 校验和、声明格式和像素/帧上限由 `image-format.mjs` 统一预检，项目打开、Agent 写入、桌面导入与浏览器首次创建图片均调用它；不能靠伪报 naturalWidth/Height 绕过真实头部尺寸限制。预检只检查压缩文件的容器结构，完整像素解码由桌面沙盒或浏览器执行，不能将两种检查混称为“所有损坏图片都能提前识别”。


## 11. 样式与文字契约（schemaRevision 9）

`Style` 保留原九字段，新增下列一级字段。全量节点/共享样式补默认，状态、动作、视图仍为稀疏覆盖。`updateNode.patch.style` 只合并一级字段，`fillPaint`、`borderSides`、`shadows` 等复合值整体替换，不能发送半个渐变对象。显式非法值不会被迁移吞掉。

| 字段 | 含义与边界 |
| --- | --- |
| `fontFamily`, `lineHeight`, `verticalAlign`, `padding` | 可为 null，使用统一默认或图片/富文本已有默认。字体是安全单个本机字体名；行高为像素1–5000；垂直位置top/middle/bottom；padding是top/right/bottom/left四边，0–1000。 |
| `italic/underline/strike`, `textCase`, `letterSpacing` | 三个布尔值；大小写none/uppercase/lowercase/capitalize；字距像素-100–1000。修改大小写呈现不改原文字。 |
| `fillPaint`, `strokePaint` | null使用原纯色。线性渐变含type:linear、angle、stops；径向含type:radial、cx/cy/radius、stops；填充另支持type:image、src、fit、positionX/Y。边框不支持图片填充。 |
| `stops` | 2–16项，含offset、color、opacity；offset在0–1且顺序非递减，可同位置形成硬边，不暗中排序。 |
| `fillOpacity`, `strokeOpacity` | 各0–1，分别作用于填充/边框；与元件整体opacity分开。 |
| `strokeStyle`, `borderSides` | solid/dashed/dotted；独立四边宽0–100或null使用strokeWidth。路径按统一strokeWidth绘制。 |
| `radiusCorners` | topLeft/topRight/bottomRight/bottomLeft四角0–50000；null使用radius；浏览器绘制按框宽高共同收敛，椭圆保持椭圆。 |
| `shadows` | 最多8项，inset、x/y、blur、spread、color、opacity；阴影不改变元件几何外框。 |
| `textShadows` | 最多8项，x/y、blur、color、opacity；按CSS顺序首项在上。 |
| `blur`, `backdropBlur` | 0–100像素；后者模糊元件背后的画面。 |
| `transition` | duration/delay为0–60000毫秒，easing为白名单；当前为可渐变的颜色、整体透明度、模糊、外阴影、变换提供过渡，纯色填充/边框及同类渐变色标支持过渡；画笔类型、图片与渐变几何等无法插值的变化即时更新，编辑画布预览不播放过渡。 |
| `transformOrigin` | x/y为0–1的框内比例，默认中心(.5,.5)。连线锚点、外框、路径拖点和切片都使用该原点。 |

填充图片只接受已验证的内嵌位图，并计入同一24 MiB展开资源上限；不同状态/视图/实例的重复图片仍重复计数，不去重。纯色选择时应显式将对应paint设null。状态样式合并当前基础外观，重置某项意味着移除该状态字段，不能用当前基础值假装继承。

命名样式规则不变：局部改外观解除关联；修改定义同步仍关联的节点。暂未实现命名样式多级继承和格式刷。编辑器状态预览只改变显示，关闭后回到项目基础外观，不生成预览命令。

富文本run保留text/bold/italic/underline/color，新增strike=false、baseline=normal（super/sub分别上下标）；旧文件仅补缺失字段。富文本弹窗编辑选区格式与段落，整体字体/行高在外观面板指定，优先于旧富文本默认。保存同时写richText与对应纯文本，保留颜色透明度和软换行。

旧editor与HTML的缺省内距原本不同，本版本统一：按钮/矩形上下4左右8；input/select上下0左右10；textarea上下9左右10；其余0，image沿用image.text.padding。默认行高为字号×1.45，richText已有倍数作为其默认。旧文件可能出现少量排版变化。显式属性在编辑器、缩略图与HTML共用绘制函数；静态缩略图不运行面板拖动/滚动和交互。

动态面板外框可设圆角，但内部状态仍使用既有矩形滚动/裁剪视口；外框圆角不会自动裁掉内部子元件的角。独立圆角、四边宽度作用于普通框；路径/连接线沿实际路径使用统一描边宽度。
